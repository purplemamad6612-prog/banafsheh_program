# بنفشه — مدیریت فروش و انبار UPVC

سامانه فارسی و راست‌چین برای فروش و پیش‌فاکتور، کالا و واحدهای چندگانه، مشتریان، تأمین‌کنندگان، گردش انبار، چک‌ها و معاملات سرمایه‌گذاری.

## آنچه در این نسخه آماده است

- **پیش‌نمایش اجرایی PWA** در ریشه مخزن (`index.html`): بدون build step و بدون وابستگی به سرویس‌های خارجی؛ رابط واکنش‌گرا برای موبایل، تبلت و دسکتاپ.
- **Flutter client** در `flutter_app/`: Flutter + Riverpod و PocketBase Dart، صفحه‌های نقش‌محور برای کالا و واحدهای نسخه‌دار، مشتریان، پیش‌نویس و فاکتور، گردش آفلاین انبار، چک‌ها، سرمایه‌گذاران/تسویه، گزارش و تنظیمات؛ فرم‌های ویرایش به PocketBase متصل‌اند. این محیط Arena فاقد Flutter/Dart SDK است، بنابراین build، analysis و تست‌های Flutter هنوز اجرا نشده‌اند.
- **PocketBase schema و server hooks** در `pb_migrations/` و `pb_hooks/`: مجموعه‌های اصلی کسب‌وکار، قواعد دسترسی نقش‌ها، محاسبه قیمت در سمت سرور، تأیید اتمیک فاکتور فروش و پردازش صف گردش آفلاین.
- **حالت نمایشی محلی**: جابه‌جایی بین ۶ نقش از منوی کاربر، ثبت فاکتور و خرید، مشتری/تأمین‌کننده، گردش موجودی، تغییر وضعیت چک، تسویه آزمایشی، خروجی CSV و ماندگاری داده‌ها در مرورگر.

> PWA ریشه مخزن یک پیش‌نمایش نمایشی و محلی است و منبع داده مالی واقعی نیست. Flutter client از PocketBase برای خواندن/نوشتن و محاسبه قیمت استفاده می‌کند؛ پیش از بهره‌برداری، Flutter build و تمام سناریوهای دسترسی، قیمت، مهاجرت و گردش آفلاین را روی PocketBase واقعی آزمایش کنید.

## اجرای پیش‌نمایش PWA

از ریشه مخزن:

```bash
python3 -m http.server 4173 --bind 0.0.0.0
```

در ویندوز می‌توانید `run-web.bat` را اجرا کنید. برای آزمایش آفلاین، ابتدا یک بار صفحه را در مرورگر باز کنید تا فایل‌های PWA cache شوند؛ عملیات گردش کالا در `localStorage` و صف محلی نگهداری می‌شود.

## راه‌اندازی PocketBase روی ویندوز

1. فایل اجرایی PocketBase را از نسخه رسمی متناسب با ویندوز دریافت و با نام `pocketbase.exe` کنار `start-pocketbase.bat` قرار دهید. فایل اجرایی و داده‌های کسب‌وکار در Git قرار نمی‌گیرند.
2. `start-pocketbase.bat` را اجرا کنید. PocketBase روی `127.0.0.1:8090` بالا می‌آید و مهاجرت‌های `pb_migrations/` را خودکار اعمال می‌کند؛ Hookهای `pb_hooks/` نیز بارگذاری می‌شوند.
3. در اولین اجرا، از صفحه نصب PocketBase یک superuser بسازید. این حساب مدیریتی PocketBase است و **با کاربر نقش «مدیر» داخل مجموعه `users` فرق دارد**.
4. در داشبورد PocketBase، داده‌های مرجع (گروه کالا، انبار، قیمت، کاربرها و موجودی افتتاحیه) را بسازید. برای ورودهای واقعی، برای هر کارمند یک Auth record در `users` با `username`, `phone`, `role`, `is_active` و گذرواژه بسازید.
5. در PWA به صفحه تنظیمات بروید و آدرس PocketBase را وارد کنید. از ثبت رمز یا توکن superuser در کد مرورگر خودداری کنید. همگام‌سازی عملیات انبار به توکن یک کاربر فعال با نقش مجاز نیاز دارد.

برای میزبانی بعدی، `pb_data/` را با نسخه پشتیبان معتبر منتقل کنید، HTTPS و محدودیت دسترسی سرور را پیکربندی و آدرس API را عوض کنید. پوشه `pb_data/` را در Git یا در فایل عمومی وب‌سرور قرار ندهید.

## ساختار PocketBase

مهاجرت اولیه ۱۹ مجموعه کسب‌وکار اعلام‌شده را حفظ/ایجاد می‌کند و سه مجموعه پشتیبان `users` (احراز هویت)، `activity_log` و `sync_queue` را نیز اضافه می‌کند. برای جداسازی امن داده‌های مالی، سه مجموعه خصوصی `product_costs`, `invoice_item_costs` و `investor_deal_costs` هم ساخته می‌شوند؛ در مجموع ۲۵ مجموعه (۲۴ پایه و یک مجموعه احراز هویت) تعریف شده است. مهاجرت روی مجموعه‌های موجود داده را حذف نمی‌کند، اما قواعد دسترسی آن‌ها را تنظیم و فیلدهای مفقود را اضافه می‌کند. PocketBase مجوزها را در سطح رکورد اعمال می‌کند، نه به‌صورت قابل اتکا روی تک‌فیلد. جداسازی اطلاعات هزینه باعث می‌شود قیمت خرید و سود بنفشه از پاسخ مجموعه‌های عمومی به فروشنده، انباردار، مشتری یا سرمایه‌گذار نشت نکند.

مبالغ پولی با **Toman صحیح** ذخیره می‌شوند. تاریخ‌های قابل‌نمایش شمسی به شکل متن Jalali نگهداری می‌شوند و فیلدهای audit خود PocketBase زمان ISO دارند. برای هر تغییر بسته‌بندی، نسخه جدید `product_units` بسازید و نسخه قبلی را ببندید؛ فاکتور و گردش انبار ضریب تبدیل همان زمان را snapshot می‌کنند.

### Hookهای مهم

- `GET /api/benafsheh/stock-summary`: جمع موجودی پایه را فقط برای مدیر، حسابدار، انباردار و فروشنده برمی‌گرداند؛ مشتری و سرمایه‌گذار نه این مسیر و نه مقدار موجودی را در UI نمی‌بینند.
- `POST /api/benafsheh/pricing/calculate`: قیمت را از هزینه محرمانه و قوانین فعال محاسبه می‌کند؛ ورودی مرورگر شامل قیمت فروش نیست. فقط مدیر در پاسخ قیمت خرید می‌گیرد.
- `POST /api/benafsheh/invoices/quote`: قیمت‌گذاری و ساخت پیش‌نویس و اقلام را در یک transaction انجام می‌دهد؛ مالک سند از نشست احرازشده سرور تعیین می‌شود.
- `POST /api/benafsheh/invoices/{id}/revise`: پیش‌نویس را با قیمت‌گذاری مجدد و جایگزینی اتمیک اقلام و snapshotها ویرایش می‌کند.
- `POST /api/benafsheh/invoices/{id}/confirm`: فاکتور draft را دوباره قیمت‌گذاری، موجودی را کنترل و گردش خروج را در یک transaction ثبت می‌کند.
- ایجاد در `sync_queue` برای انباردار و مدیر: payload را به فیلدهای گردش انبار محدود، با `sync_id` یکتا deduplicate و زمان ثبت سرور را مرجع قرار می‌دهد. انتقال بین انبارها به‌صورت دو گردش جفت‌شده در transaction ثبت می‌شود. عملیات ناموفق روی دستگاه باقی می‌ماند و از مسیر `/api/benafsheh/sync-queue/{id}/retry` (فقط انباردارِ مالک صف یا مدیر) دوباره تلاش می‌شود. کالا با کد و انبار با نام/شناسه تطبیق داده می‌شود؛ برای جلوگیری از خطای موجودی، داده‌های مرجع و موجودی افتتاحیه باید پیش از sync وارد شده باشند.

## Flutter client

در پوشه `flutter_app/` (قالب وب/PWA در `web/` آماده است):

```bash
cd flutter_app
flutter pub get
flutter run -d chrome --dart-define=POCKETBASE_URL=https://your-pocketbase-host
```

برای ساخت runnerهای بومی Windows/Android/iOS در یک Flutter SDK نصب‌شده، یک‌بار از همین پوشه `flutter create . --platforms=windows,android,ios` را اجرا کنید؛ سپس device مقصد را به `flutter run` بدهید. وابستگی‌های Flutter در `flutter_app/pubspec.yaml` تعریف شده‌اند؛ این پروژه به Flutter 3.27+ نیاز دارد. نسخه native به‌صورت پیش‌فرض از `http://127.0.0.1:8090` استفاده می‌کند؛ وب عمداً بدون URL شروع می‌شود و هیچ‌گاه به localhost وصل نمی‌شود. برای وب، URL قابل‌دسترسی PocketBase یا proxy هم‌مبدأ را در تنظیمات/`--dart-define` وارد کنید. در شبکه محدود، وابستگی‌ها را از Pub cache داخلی یا mirror مورداعتماد سازمان آماده کنید.

## امنیت و نقش‌ها

- نقش‌های رابط: مدیر، حسابدار، انباردار، فروشنده، سرمایه‌گذار و مشتری.
- بهای خرید و snapshot بهای تمام‌شده در مجموعه‌های خصوصی قرار دارد؛ نقش کاربر در ظاهر UI به‌تنهایی مرز امنیت نیست.
- قیمت فروش در Hook سرور مجدداً محاسبه می‌شود؛ `unit_sell_price` ارسالی کاربر معتبر شمرده نمی‌شود.
- قوانین PocketBase در مهاجرت تنظیم شده‌اند، اما پیش از استفاده واقعی، قواعد را با حساب‌های آزمایشی هر ۶ نقش تست کنید و CORS، HTTPS، پشتیبان‌گیری و محدودیت ایجاد superuser را بررسی کنید.
- PWA نمایشی seedهای محلی دارد؛ قیمت‌های ثابت آن نمونه‌اند و برای داده واقعی نباید منبع اعتماد یا مرجع مالی باشند.
